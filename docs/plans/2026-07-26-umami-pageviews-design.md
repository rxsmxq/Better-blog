# Umami 浏览量统一展示设计

## 目标

在文章详情、文章列表及网格卡片中展示 Umami 的页面浏览量（PV），并在 Umami 与评论系统的浏览量同时启用时优先使用 Umami。Waline 的浏览量开关默认关闭。

## 方案选择

1. 推荐：客户端请求一次按路径聚合的 Umami metrics，构建 `path -> PV` 映射并缓存。
2. 每张卡片独立请求：请求数量随卡片增长，不采用。
3. 通过 Worker 代理：可隐藏公开分享令牌，但增加部署与维护成本；当前 Umami Share API 已是公开查询入口，不采用。

## 数据流

任一需要显示浏览量的页面首次挂载时：

1. 读取 `siteConfig.analytics.umamiAnalytics.pageviews.enabled`。
2. 请求 Share API 获取网站 ID 与短期令牌。
3. 请求 `type=path` 的 metrics 接口并将所有结果规范化为路径映射。
4. 将映射写入浏览器本地缓存，缓存有效期为 5 分钟。
5. 文章详情和文章列表/网格共同读取该映射；分页切换不再请求。

若用户首次直达文章详情页，详情页同样执行以上一次批量请求并缓存映射。之后访问列表或网格直接复用缓存；不会额外发出每卡片请求。

## 优先级与降级

- 启用且配置完整的 Umami 页面浏览量优先。
- Umami 未启用或未完整配置时，保留现有评论系统浏览量作为回退。
- 请求失败时显示不可用占位符，不影响页面内容或导航。
- Waline 的 `visitorCount` 默认设为 `false`。
